# Aily Coder 全局搜索原生优化方案

## 目标

- 保持左侧搜索框“输入即搜索”，不增加 Enter 确认步骤。
- 单字符、高命中查询不阻塞 Coder iframe 的 UI 主线程。
- 保留大小写、正则、全词、包含/排除规则和结果定位。
- Coder 负责 VS Code 搜索语义；Electron 宿主只提供受路径约束的通用原生搜索能力。
- 新 Coder 遇到旧宿主时自动保留原浏览器搜索，不因版本顺序导致功能不可用。

## 原因

原 `@codingame/monaco-vscode-search-service-override` 的本地 Provider 在浏览器线程逐文件读取。每次命中都会重新拆分全文，并从文本开头计算行列；`c` 等高频字符会把这条路径放大，同时默认最多可产生 20,000 条结果，计算和结果树渲染都会占用 UI 线程。

## 实现结构

```text
Search View（500ms 防抖，输入即搜索）
  -> NativeTextSearchProvider（Coder）
     - VS Code 查询映射
     - 500 条产品默认上限
     - 新查询取消旧 requestId
  -> aily-coder-editor-native-fs postMessage
     - 能力探测
     - 工程根路径约束
  -> Electron preload / IPC
  -> rg --json（子进程）
     - 最大 1,000 条硬上限
     - 命中上限立即 kill
     - AbortController 取消
  -> 有界 preview + UTF-8 byte offset 转 UTF-16 行列
  -> Search View
```

## 查询和安全边界

- Coder 默认 `search.maxResults = 500`，宿主硬上限为 1,000。
- 输入仍自动触发，`search.searchOnType = true`，防抖为 500ms。
- 每个查询使用独立 requestId；VS Code CancellationToken 触发宿主取消 IPC。
- 宿主只允许搜索当前 Coder 工程根，拒绝越界路径。
- pattern、glob 数量/长度、文件大小、预览长度均有宿主上限。
- 默认排除 `.git`、`.aily`、`.build`、`.log`、`.workspace-history`、`node_modules` 等目录。
- `rg` 返回 UTF-8 byte offset；宿主按单向游标转换为 JavaScript UTF-16 列，避免中文和 emoji 后的定位偏移。
- 长行只回传命中附近的有界预览，不把大文件整行传回 iframe。

## 兼容与降级

Coder 初始化后先调用 `nativeSearchCapabilities`。只有协议版本、文本搜索和取消能力都满足时，才替换 `file:` 的文本 Search Provider；否则继续使用原 `@codingame` Provider。文件快速打开 Provider 不替换。

## 验收

1. 在大工程输入 `c`，无需 Enter，500ms 后自动搜索。
2. 搜索期间继续输入，旧查询被取消，界面可以继续交互。
3. 结果达到上限时显示截断状态，最多返回 500 条到 Coder。
4. `.build`、`.log`、`.workspace-history`、`node_modules` 不出现在默认结果中。
5. 中文或 emoji 之前/之后的英文命中，点击结果定位列正确。
6. 大小写、正则、全词、包含/排除输入仍生效。
7. 使用旧宿主启动新 Coder 时，仍能使用浏览器回退搜索。

- 宿主：Angular development build
